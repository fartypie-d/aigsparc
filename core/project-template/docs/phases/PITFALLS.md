# __PROJECT__ 의 함정 (상세)

> 실측으로 확인된 것만 남긴다. 프로젝트 `CLAUDE.md`에는 **한 줄 인덱스**만 두고 상세는 여기에 쓴다.
> 베이스라인 컨텍스트가 커지면 autocompact 헤드룸이 줄어든다.

## 항목 규격

항목 제목은 `## <번호>. <한 줄 제목> (<YYYY-MM-DD 실측>, <페이즈/파트>)`로 쓴다.
본문에는 다음 필드를 모두 둔다.

| 필드 | 뜻 |
|---|---|
| `trigger` | 무엇을 하면 재발하는가 — 재현 조건 |
| `changes` | 무엇이 죽는가, 대신 무엇을 해야 하는가 |
| `evidence` | 실측 근거 — 커밋 SHA · 명령과 출력 · 로그 줄 |
| `outcome` | 대응 후 실제로 어떻게 됐는가 (아직 확인 못 했으면 `미검증`) |
| `scope` | `local` = 이 저장소만 / `kit` = 키트로 전파할 것 |

`evidence` 없는 항목은 쓰지 않는다. 추론은 함정이 아니라 가설이다. `scope: kit` 항목은
키트 저장소 승격 대상이며, 승격 판정은 감독/사람이 한다.

## 1. __PROJECT__의 예시 함정은 실제 근거를 남긴다 (YYYY-MM-DD 실측, Phase N/파트 N-k)

**trigger**: __PROJECT__에서 문서화된 진입점 대신 원본 경로를 직접 호출하면.

**changes**: 호출 경로가 달라져 검증 결과가 문서 계약과 어긋날 수 있다. 문서에 적힌 진입점을 그대로
사용해야 한다.

**evidence**: `<커밋 SHA>` · `<명령과 그 출력>` · `<로그 줄>` (가상 예시).

**outcome**: 미검증

**scope**: local
