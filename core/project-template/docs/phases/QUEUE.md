# 페이즈 큐 — __PROJECT__

> 감독 세션(`/supervise-__PROJECT__`)이 `idle` 일 때 이 표에서 `approved && 선행 done && 🔴 아님` 인 항목을
> 골라 착수한다. 큐에 없는 페이즈 신설·`approved` 전환은 **사용자 확인 사항**이다.
> 상태·승인 변경은 감독 또는 사용자가 한다. 행을 지우지 않는다 — 끝난 항목은 `상태` 칸을 바꾼다.

| id | slug | 근거 문서 | 선행 | 위험 | approved | 상태 |
|---|---|---|---|---|---|---|

## 칸 규약

- `id`: 접두 + 번호(예 `F-12`·`D-3`). 한 번 붙인 id 는 재사용하지 않는다.
- `선행`: 다른 행의 id 또는 `없음`. 형제 저장소의 선행은 **그쪽 정본**(`origin/main`·`INDEX.md`)으로 확인하고 우리 행의 인용을 근거로 쓰지 않는다.
- `위험`: `낮음`·`보통`·`높음`, 🔴 위험 도메인이면 이모지를 앞에 붙인다(착수 전 사용자 승인).
- `approved`: `true` / `false` / `true (감독)` / `true (사용자, 날짜)` 처럼 **`true` 뒤에 괄호 근거를 붙여도 된다**.
- `상태`: 아래 어휘만 쓴다.

## 상태 어휘

| 값 | 뜻 |
|---|---|
| `pending` | 착수 전 |
| `in-progress` | 페이즈가 열려 있음 — `(Phase N)` 을 뒤에 붙인다 |
| `done` | 병합 완료 — `(Phase N, PR #M)` 을 뒤에 붙인다 |
| `blocked` | 선행·환경·사용자 조치 대기 — 무엇에 막혔는지 한 줄 |
| `superseded` | 다른 행이 대체 — 대체한 id |

## 🔴 `approved` 를 셀 때의 규칙 (2026-09-20 실측으로 확정)

`approved` 칸의 실제 값은 `true`·`false` 만이 아니라 `true (감독)`·`true (사용자, 날짜)`·`**true**` 같은 판이 섞인다.
⇒ **완전일치(`== "true"`)로 세면 괄호 접미가 붙은 행이 전부 조용히 탈락한다** — 한 저장소에서 완전일치 8 vs 접두일치 111 로
**13배** 갈렸다. 마크다운 강조를 벗기는 것만으로는 부족하다.

**`approved` 는 접두일치(`^true`)로 센다.** 세는 명령을 같이 적어라 — 정본 형태:

```
awk -F'|' '/^\| [A-Za-z]/{v=$7; gsub(/[ `*]/,"",v); if(v ~ /^true/) c++} END{print c+0}' docs/phases/QUEUE.md
```

「approved 이면서 미착수」는 위 조건에 `상태` 칸이 `pending` 인 것을 더해 센다 — `done` 을 부분일치로 걸면
「done 으로 적지 마라」 같은 문장을 삼킨다. 합이 안 맞으면 먼저 물어라.
