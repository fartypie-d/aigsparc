# 오케스트레이터 워크플로우 (claude → opencode 위임 → 도메인 리뷰)

> claude는 **감독관**이다. 소스 코드를 직접 수정하지 않는다.
> 구현은 `opencode run --agent <에이전트>`로 위임하고, **도메인 리뷰어**로 검수한다.
> 예외적으로 수정 가능한 것: `docs/phases/` 문서, `.claude/` 설정.

파이프라인: **인터뷰 → 크기 분류 → 지시서 → `GATE 1` → 위임(TDD; standard·large는 task-orchestrator 경유) → 도메인 리뷰 → `GATE 2`(페이즈 말 통합 승인) → 보고**

## 오토 모드 (무인 진행)

**진입**: 요청에 "오토" 키워드("오토로 진행", "오토모드")가 있을 때만 활성화한다.
시작 보고에 **"오토 모드 활성 — 선택지·게이트는 120초 무응답 시 권장안으로 자동 진행"**을 명시한다.

음성 입력 단말 경로 전제 — 일부 클라이언트는 AskUserQuestion이 120초 무응답이면 **모든 질문의
답이 문자열 `"skip"`으로 자동 채워져** 돌아온다.
일반 CLI에는 이 타임아웃이 없으므로 오토 모드여도 사용자가 응답할 때까지 대기한다(무해).

**해석 규칙 — 이것이 오토 모드의 전부다**: 답변이 `"skip"`이면 일반 모드에선 '승인 아님'이지만,
오토 모드에선 **권장안(첫 번째 "(권장)" 옵션) 채택**으로 해석한다. 질문을 생략하는 게 아니라
**정상적으로 띄우고 120초 개입 기회를 준 뒤** 진행하는 것이다 — 사용자가 보고 있으면 언제든 개입된다.
따라서 오토 모드의 모든 AskUserQuestion에는 안전한 권장 옵션이 반드시 첫 번째에 있어야 하며,
권장안을 확신할 수 없는 질문(비가역 결과가 갈리는 모호점)은 자동 채택하지 말고 해당 task를 보류한다.

**모드별 게이트 동작**:

| 지점 | 일반 모드 | 오토 모드 |
|---|---|---|
| 인터뷰 | 필수 | 필수 + **프론트로딩 강화** (아래) |
| GATE 1 (지시서 승인) | 승인 필수 | **동일 — 승인 필수.** 인터뷰 직후라 사용자 재석 중. 무인 구간은 GATE 1 이후부터 |
| 중간 선택지 | skip = 미승인, 재확인 | 120초 후 skip = 권장안 채택 + 자동 결정 로그 |
| GATE 2 (페이즈 말 통합 승인) | 승인 후 마감 | 120초 후 skip = **로컬 커밋 상태로 마감. 프로젝트 세션의 푸시는 금지** — 푸시·병합은 홈 감독 세션의 규칙(CI 초록 + SIGN OFF + 충돌 없음 + 🔴 미포함이면 자동 병합, 프로젝트 CLAUDE.md "병합 주체" 참조) |
| 🔴 위험 도메인 task (실자금 trader·운영 DB·운영 컨테이너) | 한 줄 재진술 확인 후 진행 | **자동 진행 금지** — `pending-approval` 보류, 독립 task는 계속 |
| 리뷰어 반려 🔴 | 재위임 최대 2회 → 중단 | **동일 — 완화 없음.** 반려를 권장안으로 통과시키지 않는다 |
| 검수·리뷰어 호출 | task마다 필수 | **동일 — 생략 금지** |

**인터뷰 프론트로딩**: 오토 모드의 인터뷰는 마지막 확실한 개입 기회다. 스코프·우선순위·제약에
더해, 지시서 작성 중 갈릴 것으로 예상되는 **설계 분기점을 미리 선택지로 해소**한다
(최대 2라운드 × 4질문). 그러고도 비가역 모호점이 남으면 오토 진입을 거부하고 일반 모드를 제안한다.

**자동 결정 로그**: skip으로 채택된 모든 결정과 자동 커밋(해시 포함)을 지시서
(`docs/phases/PHASE<번호>_<slug>.md`)의 `## 자동 결정 로그` 섹션에 `[시각] 질문 → 채택안 (사유)` 형식으로
기록한다. 9단계 완료 보고에 **로그 전체 + 보류 task 목록**을 포함한다 — 복귀한 사용자가
무엇이 자기 없이 결정됐는지 감사(audit)할 수 있어야 한다.

**보류 task 처리**: 보류된 🔴 task는 완료 보고에 명시하고, 다음 사용자 발화에서
AskUserQuestion으로 승인을 받은 뒤에만 진행한다.

## ECC 사용 원칙 (전 프로젝트 공통)

ECC는 **플러그인이 아니라 `install.sh`로 `~/.claude/`에 설치된 수동 설치본**이다
(공식 문서 옵션 2). 플러그인은 rules를 배포하지 못하므로 이 방식이 rules를 얻는 유일한 경로다.
따라서 커맨드는 짧은 형태(`/plan`)를 쓴다 — `/ecc:plan` 네임스페이스 형태가 아니다.

**리뷰어·에이전트는 ECC를 기본으로 삼는다.** 새 리뷰어를 만들기 전에 ECC에 대응물이 있는지 먼저 확인한다
(`~/.claude/agents/` 67종). 프로젝트 리뷰어는 **ECC에 대응물이 없는 도메인에만** 만든다.

| 계층 | 위치 | 수정 |
|---|---|---|
| ECC 기반 | `~/.claude/agents/`, `skills/ecc/`, `rules/ecc/` | **금지** — `install.sh` 재실행 시 덮어써진다 |
| 프로젝트 커스텀 | `<프로젝트>/.claude/agents/`, `task-templates/` | 여기서만 커스텀 |

커스텀이 필요하면 ECC 파일을 고치지 말고 **같은 이름으로 프로젝트 `.claude/agents/`에 사본**을 두거나,
ECC에 없는 도메인이면 새 프로젝트 리뷰어를 만든다. 프로젝트 리뷰어는 로스터에 근거(왜 ECC로
안 되는지)를 한 줄로 남긴다.

> ECC 스킬 중 이 프로젝트들과 무관한 언어·프레임워크 43종은 `~/.claude/ecc-skills-inactive/`로
> 격리되어 있다 (opencode 위임 에이전트 컨텍스트 절감). 필요해지면 다시 옮기면 된다.

## 병렬 세션 (한 프로젝트 동시 작업)

같은 프로젝트에서 두 세션 이상이 동시에 작업할 때의 규약 (Phase 134/135 동시 진행으로 실증):

1. **메인 체크아웃 = 안정 전용** — 메인 체크아웃은 항상 기본 브랜치(develop 등)를 유지하고
   읽기·조사·병합·릴리스만 한다. **소스 변경이 있는 페이즈는 세션 수와 무관하게 무조건
   워크트리에서** 진행한다 (입력 단말 불문): `bash scripts/phase-claim.sh <slug>` 가
   번호 발급 + `git worktree add` 를 flock으로 원자 처리하고 `PHASE=/WORKTREE=/BRANCH=` 를
   출력한다. **워크트리 안에서 브랜치를 갈아타지 말 것** — 다른 브랜치가 필요하면 새로
   claim한다 (166 워크트리 디렉터리명·브랜치 불일치 실측). 워크트리가 격리하는 것은
   **파일뿐** — opencode 전역 세션 DB·venv·포트는 공유다. 마감은 `bash scripts/phase-close.sh <N>`.
2. **위임 직렬화** — opencode 위임은 반드시 `scripts/run-delegation.sh` 경유.
   `~/.config/opencode/serve.env`가 있고 serve attach가 가능하면 프로젝트별 락을 쓴다.
   프로젝트가 다르면 병렬로 실행되고, 같은 프로젝트(워크트리 포함)는 직렬 대기
   (`LOCK_WAIT(project)`, 최대 30분)가 된다. serve 환경이 없거나 기동에 실패하면
   standalone 폴백으로 전역 락을 써 전체를 직렬화한다(`SERVE_FALLBACK`, `LOCK_WAIT`).
   단독 병렬은 업스트림이 고칠 계획 없음으로 확정한 busy_timeout=0 → SQLITE_BUSY 결함
   (anomalyco/opencode#21215 · #15188)으로 토큰 0개·exit 0 침묵사가 나므로 금지하며,
   병렬은 serve 경유만 허용한다. 호출 cwd는 저장소 루트여야 한다(스크립트 내부 `cd` 없음;
   프로젝트 락 이름과 `--dir`이 호출 cwd 기준). LOCK_TIMEOUT이 나면 침묵 대기하지 말고 보고한다.
3. **지시서 분리** — 지시서는 `docs/phases/PHASE<번호>_<slug>.md` (5단계). `CURRENT_TASK.md`는
   docs-index가 싱글턴으로 특별 취급하므로 동시 페이즈가 하나뿐일 때만 쓴다.
   페이즈 번호는 `phase-claim.sh` 가 발급한 것만 쓴다 — `ls docs/phases/` 육안 확인은 다른
   워크트리·브랜치의 지시서가 보이지 않아 충돌한다 (Phase 145 중복·166→167 리네임 실측).
4. **산출물 분리** — `.orchestrate/task<N>.prompt`·`task<N>.log` 명명 고정 (워크트리별로는
   자연 분리, 같은 체크아웃 안에서는 task 번호로 구분).

## 0단계: 프로젝트 로스터 로드

현재 프로젝트의 `.claude/orchestrate.md`(로스터)를 읽는다. 로스터에는
**에이전트 목록·모델·리뷰어 매핑·TDD 규정·도메인별 검증 명령**이 있다.
로스터가 없으면 중단하고 사용자에게 보고 (로스터 없이 위임 금지).

`.claude/task-templates/`가 있으면 해당 도메인 템플릿도 4단계에서 읽는다.

## 1단계: 상태 수집 (읽기 전용)

- `docs/phases/TODO.md`, 진행 중 지시서(`docs/phases/PHASE*.md` 중 `status: in-progress`, 없으면 `docs/phases/CURRENT_TASK.md`)
- `git log --oneline -10`, `git status --short`, `git diff --stat HEAD`
- `docker ps` + 로스터에 명시된 헬스체크
- **훅 생존 확인** — 이 키트를 도입한 프로젝트는 SessionStart 훅(settings.json)이 `scripts/hook-selfcheck.sh`를
  자동 실행한다 (2026-07-29 편입 — 스킬 단계만으로는 스킵된 실측 사례 대응). 세션 시작 컨텍스트에
  `HOOK_SELFCHECK_PASS`가 없으면 수동 실행하고, FAIL이면 원인 확인 전 위임 금지.
  ECC 실측 교훈: 훅은 조용히 죽고, 죽은 동안 가드가 사라진다. 스크립트 없는 프로젝트는 생략.
  주의: 이 스크립트는 훅 스크립트 자체를 실행해 검증하므로 "설정이 하네스에 로드됐는지"까지는
  증명하지 못한다 — 사용 중인 클라이언트가 `settingSources: ["user","project"]`로 프로젝트 설정을
  로드하는지 확인해 둘 것(2026-07-29 실측).

## 2단계: 인터뷰 (필수)

> **입력 환경**: 사용자가 **음성 → STT 변환** 단말로 입력할 수 있다.
> 긴 타이핑이 어려운 환경을 전제로, 모호점은 반드시 **AskUserQuestion 선택지**로 물어 '고르게' 한다.
> 질문은 한 번에 최대 4개, 각 질문에 **추천 옵션을 첫 번째로** 두고 "(권장)"을 붙인다.

### STT 오인식 대응 (음성 입력 전제)

입력에 오타가 섞이는 것은 **정상이다.** 문맥으로 복원되는 오타는 그냥 알아듣고 진행한다.
되묻는 비용이 더 크므로 사소한 오타마다 확인하지 말 것.

다만 아래 **세 범주는 문맥으로 복원하지 말고 반드시 확인**한다 — 잘못 알아들으면 되돌릴 수 없다:

| 범주 | 왜 위험한가 | 대응 |
|---|---|---|
| **부정어** | "건드리지 마" ↔ "건드려", "하지 말고" ↔ "하고" 가 통째로 뒤집힌다 | 금지·제약 지시로 해석되면 **재진술 후 선택지 확인** |
| **숫자** | 포트·테이블 수·개수·금액. 57↔67, 9102↔9120 처럼 한 음절 차이 | 명령·검증에 쓰기 전 재진술 |
| **고유명사** | 에이전트·DB·컨테이너 이름. 프로젝트 `CLAUDE.md`의 사전 참조 | 사전에 없고 확신 없으면 후보를 선택지로 제시 |

**게이트는 자유 서술이 아니라 선택지로 받는다.** GATE 1(지시서 승인)·GATE 2(커밋 승인)에서
"승인"을 음성으로 받으면 부정어 유실 위험이 있다 → **AskUserQuestion으로 승인/수정/중단을 고르게 한다.**

위험 작업(운영 DB·실자금 거래·운영 컨테이너·`rm`·`DROP`) 직전에는 **한 줄 재진술**을 먼저 한다:
> "확인: `myapp_test` 만 삭제하고 다시 만듭니다. 운영 DB `myapp` 은 건드리지 않습니다. 맞습니까?"

지시서 작성 **전에** 모호점을 해소한다. 확인 항목:
1. **스코프** — 요청이 어디까지인가 (포함/제외 경계)
2. **우선순위** — 여러 작업이면 순서, 일부만 먼저 할지
3. **제약** — 건드리면 안 되는 것, 마감·품질 수준, 배포 여부

음성 입력은 짧고 생략이 많다 — 요청이 완전히 명확한 경우는 드물다고 전제한다.
생략은 스코프·우선순위·제약이 **모두** 명시된 경우에만 하며, 생략 시
"인터뷰 생략: 스코프·우선순위·제약이 모두 명시됨"을 한 줄로 보고한다.

### 비판적 검토 (동의 전 필수)

사용자 요청을 그대로 수용하지 말고 지시서 작성 전에 검토한다:
- 더 단순하거나 안전한 대안이 있으면 **먼저 제시**한다
- 기존 구조·안전 규칙(실자금 거래 모듈, 운영 컨테이너, 외부 계정 자격증명)과 충돌하면 지적한다
- 비용 대비 효과가 낮은 범위는 축소안을 제안한다

무조건적 동의는 금지. 근거와 함께 반론을 제시하고, 사용자가 반론을 듣고 "그래도 진행"이라 하면 그때 따른다.

## 3단계: 크기 분류

의식(ceremony)은 영향 범위에 비례한다. 세 신호 중 **가장 높은 등급**을 택하고 한 줄로 보고한다.

| 등급 | 파일 수 | 계약 변경 | 설계 모호성 | 절차 |
|---|---|---|---|---|
| trivial | 1개, 몇 줄 | 없음 | 없음 | 위임 → 검수 (지시서 3줄로 축약) |
| small | 1파일/1함수 | 없음 | 코드 읽으면 명확 | 간이 지시서 → 위임 → 검수 |
| standard | 2~5파일 | 내부 모듈 추가 | 선택지 하나 | 전체 절차 |
| large | 다수/횡단 | 외부 의존성·공개 API·스키마 | 미해결 질문 다수 | 전체 절차 + task 분할 |

**예외**: ⚠️/🔴 도메인이거나 DB 스키마·인증·결제를 건드리면 파일 수와 무관하게 **최소 standard**.

## 4단계: task 세분화 + 도메인 템플릿

미완료 항목 + 사용자 요청을 독립 task로 분해한다. **task 크기 기준(모두 충족)**:
- 대상 파일 **1~3개** (같은 도메인 내)
- 검증 명령 **1~2개**로 완료 판정 가능
- "이 task만 롤백해도 나머지가 정상 동작"하면 독립 task
- 지시서 본문이 화면 한 장(~40줄)을 넘으면 더 쪼갠다

task마다 **에이전트**(로스터에서 선택) + 의존 순서를 배정한다.

### 모델 배정 — 중앙 정책 + 자동 폴백 (2026-08-01)

모델은 에이전트 frontmatter가 아니라 **프로젝트 정책을 우선하고 host 정책으로 폴백하는 tier 체인**에서
나온다 — `run-delegation.sh`는 먼저 `<git 최상위>/.claude/model-policy.json`을 찾고, Git 저장소가
아니면 `<호출 cwd>/.claude/model-policy.json`을 찾은 뒤 `~/.config/opencode/model-policy.json`으로
폴백한다. 체인 순서대로 `-m`을 주입하고, 한도·무응답(429/quota/즉시 실패)과 `status 402`,
`insufficient credits`, `credit balance is too low`, `usage limit reached`를 포함한 크레딧 오류를
감지하면 **자동으로 다음 모델로 재시도**한다. 실제 정책은 `POLICY_USED=<경로> (project|host)`로
stdout과 `.wrapper` 로그에 기록한다. 두 정책 파일이 모두 없으면 exit 64로 종료하며 두 후보 경로를
오류에 표시한다. frontmatter의 `model:`은 수동 실행용 안전 기본값일 뿐이다.

프로젝트 정책은 저장소에 추적·커밋되므로 이를 바꿀 수 있는 사람이 위임 모델 선택에 영향을 줄 수 있다.
따라서 PR에서는 정책 파일의 diff도 코드 변경과 같은 눈높이로 검토한다. `model-doctor.sh`는 host 정책을
기본값으로 검사하므로 프로젝트 정책은 `--policy .claude/model-policy.json`으로 검증한다. 서브모듈이나
중첩 저장소에서 호출하면 `git rev-parse --show-toplevel`이 중첩 루트를 가리키므로 의도한 저장소
루트에서 실행한다.

| tier | 체인 | 쓰는 곳 |
|---|---|---|
| `default` (생략 시) | gemini-3.6-flash-high → qwen3.7-plus → deepseek-v4-pro → deepseek-v4-flash-0731 | 일반 task |
| `heavy` | grok-4.5 → qwen3.7-max | **large 등급·🔴 위험 도메인 task는 처음부터 heavy** + 리뷰어 🔴 반려 후 재위임(자동 승격) |

task별 지정: 지시서 task에 선택 필드 **`모델:`** 을 쓰면 `run-delegation.sh` 4번째 인자로
전달한다 — `heavy` 또는 `provider/model`(그 모델 우선, 실패 시 default 체인 폴백).
생략하면 default. **판정·보고는 스크립트가 출력하는 `MODEL_USED=`(실사용 모델) 기준**이다.

> 모델 ID는 `~/.config/opencode/opencode.json`의 `models{}`에 등록된 것만 유효하다
> (`opencode models`로 확인). 미등록 ID는 서버 에러로 실패한다. 예외: `xai/*`는 `/connect`
> OAuth 빌트인이라 등록 없이 유효. API 키는 `~/.config/opencode/secrets.env`에서 `{env:...}`로 주입된다.

**각 task의 도메인 템플릿을 `.claude/task-templates/<도메인>.md`에서 읽고**, 그 템플릿의
Task 필드·체크리스트·금지사항·"위임 프롬프트에 반드시 포함"을 지시서에 반영한다.
템플릿이 없는 프로젝트는 로스터만으로 진행한다.

### 재사용 조사 (필수 — 중복의 주된 원인)

위임 에이전트는 컨텍스트가 좁아 **기존에 무엇이 있는지 모르면 새로 만든다.**
중복은 에이전트의 실수가 아니라 **지시서의 누락**이다. 찾는 일은 지시서를 쓰는 쪽의 책임이다.

task를 쓰기 전에 기존 자산을 검색한다 (`grep -rn`으로 핵심 동사·명사 양쪽, 공용 유틸 디렉터리 확인).
도메인이 낯설거나 large 등급이면 **`code-explorer` 에이전트**로 기존 실행 경로를 먼저 추적한다.

조사 결론을 각 task의 **`재사용` 필드**에 적는다 — 셋 중 하나:
- `그대로 재사용 <경로>:<이름>` — 새로 만들지 말 것을 명시
- `개선 후 재사용 <경로>:<이름> (호출부 N곳)` — 하위 호환 요구와 호출부 목록을 함께 제공.
  호출부가 5곳을 넘으면 별도 task로 분리
- `없음 — <검색어>로 조사` — **근거 없는 '없음'은 조사 누락이다**

프로젝트에 `.claude/task-templates/_reuse-rules.md`가 있으면 그 규칙을 우선 적용한다.

### 전제 실측 (standard·large 필수 — ECC 실측: 재작업 3회 이상을 착수 전에 제거)

지시서가 의존하는 전제 — 함수 시그니처·타입·설정 키·픽스처 경로·"이미 그렇게 동작한다"는
믿음 — 를 작성 **전에** Read/Grep으로 실측한다. 기억·문서·이전 지시서에서 온 전제는
실측 전까지 **미검증**이다. 결과는 지시서 인덱스의 `## 전제 실측` 표에 기록:
`전제 | 근거 <파일:라인> | 유지/뒤집힘`. **뒤집힌 전제**는 해당 task 본문에 반영한다 —
구현 후에 발견되면 task가 아니라 페이즈 재작업이 된다.

실자금 거래·결제 등 🔴 도메인 task는 다른 도메인 task와 섞지 않는다 (독립 배정).

## 5단계: 지시서 작성 → `docs/phases/PHASE<번호>_<slug>.md` → **GATE 1**

지시서는 **`docs/phases/PHASE<번호>_<slug>.md`** 에 쓴다 (`CURRENT_TASK.md`는 동시 진행 페이즈가
하나뿐일 때만 허용 — docs-index가 싱글턴으로 특별 취급해 병렬 세션 간 덮어쓰기 충돌이 난다).
페이즈 번호·워크트리·브랜치는 **`bash scripts/phase-claim.sh <slug>` 출력값을 그대로** 쓴다.
번호를 육안으로 고르지 말 것 (레지스트리가 유일한 진실의 원천 — 병렬 세션 충돌 실측 2건).

### 파일 구조 — task 3개 이상이면 분할 필수 (Phase 179 스래싱 실측 대응)

단일 지시서가 자라면 압축 후 재읽기 대상이 통째로 커져 autocompact 루프를 만든다
(72KB 지시서 → 압축 직후 +31K 토큰 재읽기 → 3턴 만에 재압축 → 세션 사망, 2026-08-06 실측).

| 구조 | 조건 | 구성 |
|---|---|---|
| **분할 (기본)** | task 3개 이상 또는 large 등급 | 인덱스 `docs/phases/PHASE<번호>_<slug>.md` (**10KB 상한**) + task별 상세 `docs/phases/PHASE<번호>_<slug>.tasks/task<N>.md` |
| 단일 파일 | task 2개 이하 소형 페이즈 | `docs/phases/PHASE<번호>_<slug>.md` 하나 (**20KB 상한**) |

- **인덱스**에 두는 것: frontmatter, 인터뷰 결과, task 목록 표(번호·제목·에이전트·상태·커밋),
  자동 결정 로그, **전파 제약 누적**. 진행 중 갱신은 인덱스에만 한다.
- **task 파일은 frontmatter로 시작한다** — `task: <번호>`·`status: pending|in-progress|done|blocked|superseded`.
  상태 전이는 표 수정이 아니라 `python3 scripts/phase-tools.py tasks <phase> --set <N>=<status>`로
  갱신한다 (기계 판독 단일 소스 — 무인 드라이버·대시보드가 이 값을 읽는다. 조회:
  `tasks <phase>` JSON, 다음 실행 대상: `tasks <phase> --next`).
- **파트 그룹핑 (세션 단위 계획)**: 한 세션에 다 못 끝낼 phase는 인덱스에서 task를
  **파트**로 묶는다 — `## 파트 <phase>-1 (세션 1): Task 1~3` 식. **파트 경계 = 세션 경계 =
  HANDOFF 시점**이다. 인계를 임기응변으로 만들지 말고 지시서 작성 시점에 계획할 것.
  파트는 표기·계획 단위일 뿐 phase 번호·워크트리·브랜치는 그대로 하나다
  (레지스트리는 정수 번호만 발급한다).
- **task 파일**에 두는 것: 아래 Task 필드 포맷 전체 + 해당 task의 위임 로그 요약·반려 이력.
  `.tasks/` 하위는 docs-index 스캔 대상이 아니므로 frontmatter 불필요.
- 상한 초과가 예상되면 내용을 task 파일로 내린다. 인덱스가 10KB를 넘기기 시작하는 것이
  페이즈를 쪼개라는 신호다.

인덱스 frontmatter·인터뷰 결과 포맷:

```markdown
---
phase: [번호]
date: YYYY-MM-DD
kind: task
domain: [backend, worker 등 콤마 구분]
status: in-progress
commits: -
cost: -
compactions: 0
interventions: 0
summary: [한 줄 요약 — 인덱스 표에 그대로 나온다]
---

# 작업 지시서 — [요청 요약] (YYYY-MM-DD)

## 인터뷰 결과
- 스코프: ... / 우선순위: ... / 제약: ...
- 크기 등급: [trivial|small|standard|large]
```

task 상세 포맷 (분할 구조에선 `.tasks/task<N>.md`, 단일 파일에선 인덱스에 이어서):

```markdown
## Task N: [제목]
- **에이전트**: [로스터의 에이전트명]
- **모델**: [생략=default | heavy | provider/model — large·🔴 도메인은 heavy] (선택 필드)
- **대상 파일**: [1~3개 경로]
- **선행**: [Task 번호 또는 없음]
- **목표**: [완료 시 동작해야 하는 것 1~2문장]
- **재사용**: [그대로 재사용 <경로>:<이름> | 개선 후 재사용 <경로>:<이름> (호출부 N곳) | 없음 — <검색어>로 조사]
- **실패 테스트**: [테스트 파일::테스트명 + 무엇을 검증하는지]
  └ 작성 불가 시: **불가 사유** + 대체 검증 (로스터의 대체 검증 표 참조)
- **필독 스킬**: [kebab-case 스킬명]
- **필수 규칙**: [이 task에만 필요한 2~3줄 + 도메인 템플릿의 금지사항]
- **완료 조건**: [검증 명령 1~2개 + 기대 결과]
```

### 리뷰 예상 지점 — RED 사전 고정 (standard·large 필수)

인덱스에 `## 리뷰 예상 지점` 표를 쓴다: **리뷰어가 🔴를 낼 가능성이 가장 높은 지점 1~3개** —
`지점(파일·동작) | 예상 지적 | 고정 RED 테스트(파일::테스트명, 담당 task)`. 그 RED 테스트를
담당 task의 `실패 테스트` 필드에 포함시켜 **착수 시점에 먼저 작성**하게 한다.
ECC 실측: 이 사전 고정이 리뷰 3라운드(BLOCK×2)를 1라운드 SIGN OFF로 줄였다 (표본 4개 재현).
7단계 리뷰어 호출 시 이 표를 전달물에 포함한다.

**GATE 1** — 지시서를 사용자에게 제시하고 **승인을 받은 뒤에** 위임을 시작한다.
trivial 등급은 게이트를 생략할 수 있으나, 생략했음을 한 줄로 보고한다.
오토 모드에서도 GATE 1은 skip을 승인으로 치지 않는다 — 명시 승인 필수 ("오토 모드" 절 참조).

## 컨텍스트 안전 규칙 (autocompact 스래싱 방지)

경량 단말 경로는 압축 임계가 낮아 헤드룸이 작다. 압축 요약이 문서 내용을 잃으면 "다시 읽자"가
되는데, 그 대상이 크면 **압축→재읽기→재압축 루프**로 세션이 죽는다 (Phase 179, 2026-08-06 실측).

1. **압축(요약 재개) 후 지시서 전체 재읽기 금지** — 인덱스 + **현재 task 파일만** 읽는다.
   이미 완료된 task의 상세는 인덱스의 상태 표와 전파 제약 누적으로 충분하다.
2. **20KB 넘는 파일은 통째로 Read 금지** — Grep으로 위치를 찾고 offset/limit 부분 읽기.
   위임 로그는 `tail`로만 확인한다 (전체 cat 금지).
3. **세션 인계 의무** — 스래싱 경고가 뜨거나 한 세션에서 압축이 2회를 넘으면 진행을 멈추고
   `docs/phases/PHASE<번호>_<slug>.tasks/HANDOFF.md`를 쓴다: 완료 상태표 + 다음 task 번호 +
   전파 제약 누적 + 재개 지시 한 줄. 커밋 후 사용자에게 **"새 세션에서 재개"**를 안내하고 끝낸다.
   이어받는 세션은 HANDOFF + 현재 task 파일만 읽고 시작한다 (지시서 전체 금지).
4. 긴 페이즈는 지시서 작성 시점에 **파트 그룹핑**(5단계 참조)으로 세션 단위를 계획한다 —
   파트가 끝나면 스래싱 경고가 없어도 HANDOFF를 쓰고 세션을 넘긴다. "1페이즈 = 1세션"은
   상한이지 목표가 아니다.

## 이벤트 로그 (events.jsonl) — 기계가 읽는 진행 기록

phase 리포트(usage-dashboard, `docs/phase-report-data-sources.md`)가 로그 파싱 없이 위임
트리를 재구성할 수 있도록, 아래 시점마다 **메인 체크아웃의 `.orchestrate/events.jsonl`**
(append-only)에 JSON 한 줄을 남긴다. **워크트리 phase도 메인 체크아웃 절대경로에 쓴다** —
워크트리 `.orchestrate/`는 phase-close 때 워크트리와 함께 사라지고, append 한 줄은 phase
필드로 구분되므로 병렬 세션이 한 파일을 써도 안전하다.
**누락은 실패가 아니다** — 기록 실패로 보고·검수를 멈추지 말고 다음 이벤트부터 재개한다
(사후 파서가 문서·git에서 소급 보정한다).

기록은 heredoc이 아니라 **printf 단일 호출 + 절대경로**로 (bash-guard·인용부호·
백그라운드 cwd 함정 회피):

```bash
printf '%s\n' '{"ts":"'"$(date -Is)"'","phase":179,"part":"179-6","task":"8","event":"delegation_done","agent":"redis-queue","model":"xai/grok-4.5","exit":0}' >> "$CLAUDE_PROJECT_DIR"/.orchestrate/events.jsonl
```

공통 필드: `ts`(`date -Is`), `phase`(정수), `part`(`"<N>-<k>"`, 모르면 생략),
`task`(문자열 — `"4b"` 허용), `event`. 이벤트별 추가 필드:

| event | 시점 | 추가 필드 |
|---|---|---|
| `phase_claimed` | phase-claim 직후 | `slug`, `branch` |
| `part_started` | 파트 작업 시작 (세션 시작) | `session`(uuid, 알면) |
| `gate_asked` / `gate_answered` | GATE 1·2·실증(배포) 게이트 | `gate`(`gate1`\|`gate2`\|`deploy`), answered엔 `answer`(`approve`\|`reject`\|`skip`) |
| `delegation_started` / `delegation_done` | 6단계 위임 직전/완료 통지 후 | `agent`, done엔 `model`(`MODEL_USED=` 실측값)·`exit` |
| `review_verdict` | 7단계 판정 직후 | `reviewers`(배열), `verdict`(`pass`\|`reject`), `red`·`orange`(개수), `reject`일 때만 `reject_cause`(`model`\|`instruction`\|`spec`\|`unknown`) |
| `task_committed` | task 로컬 커밋 후 | `commit`(해시) |
| `handoff_written` | HANDOFF 작성 시 | `next_task` |
| `phase_closed` | phase-close 후 | — |

`.orchestrate/`는 gitignore 대상이라 이벤트는 커밋되지 않는다(호스트 로컬이 소스).
phase-close 아카이브(`p<N>-*` 패턴)와 janitor 오래된 파일 정리는 `events.jsonl`을
건드리지 않는다 (phase-tools.py가 예외 처리, 2026-08-07).

## 6단계: 위임 실행 (TDD)

### 경로 분기 — 등급에 따라 실행 주체가 다르다

| 등급 | 실행 주체 |
|---|---|
| **standard·large** | task마다 **`task-orchestrator` 서브에이전트**를 Agent 툴로 호출 (아래 6-A) |
| **trivial·small** | 메인이 `scripts/run-delegation.sh`로 직접 위임 (아래 6-B) |

### 6-A. task-orchestrator 경유 (standard·large)

task당 3~5만 토큰의 위임 출력·로그·왕복이 메인 컨텍스트에 쌓이는 것을 막는다
(Phase 135가 46만 토큰에서 세션 절단된 사고의 근본 대응 — "1페이즈 = 1세션" 복원).

> **위임 실행은 메인 전속이다.** 서브에이전트에게 백그라운드 위임을 맡기면 서브 턴 종료 시
> 자식 opencode 프로세스가 함께 죽는다 (2026-07-29 실측). 서브는 위임 **결과**만 다룬다.

1. 메인이 위임 프롬프트를 `.orchestrate/task<N>.prompt`로 작성하고(구성 규칙은 6-B와 동일)
   `scripts/run-delegation.sh`를 백그라운드 Bash로 실행, 완료 통지를 받는다.
2. 완료 후 **task-orchestrator를 호출**한다. **전달물**: 해당 task 파일 전체(분할 구조) 또는
   지시서의 해당 task 섹션(단일 파일) — 재사용 필드 포함 + **인덱스의 "전파 제약" 누적분** +
   위임 로그 경로(`.orchestrate/task<N>.log`). 전체 지시서를 붙여넣지 말 것.
3. task-orchestrator가 로그 확인 → 경계·TDD 확인 → 도메인 검증 → **로컬 커밋**까지 수행하고
   보고 형식(커밋 해시/검증 결과/변경 파일/다음 task 전파 제약/에스컬레이션)으로 반환한다.
   검증 실패 시 서브는 `.orchestrate/task<N>-fix.prompt`를 작성해 **"재위임 필요"로 반환**하고,
   재위임은 메인이 실행한 뒤 서브를 다시 호출한다 (동일 task 최대 2회).
4. 보고 접수 후 메인은: ① 보고의 "전파 제약"을 지시서 해당 섹션에 반영 ② 7단계 검수(리뷰어 병렬 호출)
   ③ 판정 후 다음 task 기동. **에스컬레이션 보고가 오면 진행을 멈추고 사용자에게 보고한다.**
5. 반려 시: 리뷰어 findings를 fix.prompt에 붙여 **메인이 heavy tier로 재위임 → task-orchestrator
   재호출** (`run-delegation.sh ... heavy` — 🔴 반려 후 재위임은 자동 heavy 승격. 수정 커밋 추가, 최대 2회).

### 6-B. 직접 위임 (trivial·small) — 반드시 이대로 (2026-07-22~23 사고 반영)

**1) 프롬프트를 파일로 먼저 저장 (긴 인용부호 이스케이프 사고 방지):**

산출물(프롬프트·로그)은 **/tmp가 아니라 프로젝트 내 `.orchestrate/`** 에 두고,
파일명은 **`task<N>.prompt` / `task<N>.log`** 로 고정한다 (병렬 세션·다중 task 충돌 방지).
이유: 완료 알림 turn에서는 cwd 밖 경로(/tmp 포함)를 만지는 Bash가 권한 프롬프트를 띄울 수 있다.

```bash
mkdir -p .orchestrate
install -m 600 /dev/null .orchestrate/task<N>.prompt
# 경로가 재사용되면 umask 만으로는 기존 파일 권한이 남는다.
cat > .orchestrate/task<N>.prompt <<'PROMPT'
<위임 프롬프트>
PROMPT
```

**2) 실행 — `scripts/run-delegation.sh` 를 백그라운드 Bash 하나로** (`run_in_background`):

```bash
bash scripts/run-delegation.sh <에이전트> .orchestrate/task<N>.prompt .orchestrate/task<N>.log [tier|모델]
```

4번째 인자는 지시서 task의 `모델:` 필드 그대로 (생략=default, `heavy`, `provider/model`).
스크립트에 프리플라이트·serve attach 프로젝트별/standalone 전역 flock·API 키 자가 주입·init 워치독·PID 완료 대기·
**모델 폴백 체인**(4단계 참조)이 전부 내장되어 있다. exit 코드로 판정한다:
래퍼 진단 신호(`MODEL_FALLBACK`·`LOCK_WAIT`·`SESSION_ABORTED`·`MODEL_USED=` 등)는 `<로그파일>.wrapper`에도 남으므로, 폴백·락 대기의 사후 확인은 그 파일을 본다.

| exit | 의미 | 대응 |
|---|---|---|
| 0 | 정상 완료 (`DONE` + `MODEL_USED=` + 로그 tail 출력) | 7단계 검수로. `FALLBACK_HISTORY`가 있으면 완료 보고에 명시 |
| 2 | `STALLED_AT_INIT` — init 단계 세션 DB 경합 (산출물 없음, kill 안전) | 잔여 opencode 정리 후 재위임 |
| 3 | `PREFLIGHT_UNMANAGED` — **standalone 폴백 경로에서만** 락 없이 도는 비관리 opencode 프로세스 | 프로세스 확인·정리 후 재시도 |
| 4 | `LOCK_TIMEOUT` — 30분 내 락 획득 실패. 상태 디렉터리 또는 로그 파일 생성 실패도 같은 exit 4 | 침묵 대기 금지 — 사용자에게 보고 |
| 5 | `MODEL_EXHAUSTED` — 체인 전 모델 실패 (전원 한도/장애) | 침묵 재시도 금지 — 사용자에게 보고 (한도 갱신 대기 or 정책 파일 조정) |
| 6 | 고아 세션 가능성 — 클라이언트를 정리했으나 서버 세션 abort를 확인하지 못함 | `bash scripts/opencode-serve-ctl.sh sessions`로 확인 |
| 7 | `AGENT_NOT_FOUND` — 없는 에이전트가 기본 에이전트로 조용히 폴백(rc=0)하는 것을 래퍼가 감지 | 로스터에서 에이전트명 확인 후 재위임 |
| 8 | `WALLCLOCK_CAP` — 총 벽시계 상한 초과 (기본 3600초, `ORCHESTRATE_DELEGATION_MAX_SEC`로 조정) | 로그 확인 후 범위를 쪼개 재위임. 폴백하지 않으므로 침묵 재시도 금지 |
| 64/66 | 사용법·정책 파일 오류 / 프롬프트 파일 없음; 64의 `WALLCLOCK_CAP_INVALID`: 손상된 `ORCHESTRATE_DELEGATION_MAX_SEC`(비수치·음수·허용 범위 초과)는 착수 전 거부. 빈 값·`0`은 정당한 비활성 형태 | 호출 수정 |

> 스크립트가 없는 프로젝트(신규)에는 키트의 `core/scripts/run-delegation.sh`를
> 복사해 설치한다. 워치독·pgrep 함정의 배경은 프로젝트 CLAUDE.md "이 저장소의 함정" 참조.

**금지 — 이 세 가지가 실제로 사고를 냈다:**

| 하지 말 것 | 이유 |
|---|---|
| `timeout N opencode run ...` | SIGTERM이 **작업 중인 에이전트를 죽인다.** 게다가 opencode의 SQLite 세션 DB 트랜잭션이 정리되지 않아 **다음 실행이 세션 생성 단계에서 무한 대기**하고, 그것도 죽이면 연쇄된다 |
| `opencode run ... \| tail -N` | 파이프 버퍼링으로 **진행 상황이 전혀 안 보인다.** 죽으면 버퍼 내용도 사라진다 |
| 프롬프트를 명령줄에 직접 인라인 | 따옴표·백틱 이스케이프가 깨진다. 반드시 파일 경유 |

### 완료 알림 turn(백그라운드 위임 완료 후 자동 재개된 turn) — 2026-07-24 근본 패치로 해소

**기본 규칙: 이 turn에서도 AskUserQuestion을 정상적으로 쓴다.** 스트리밍 입력을 지원하는
클라이언트는 백그라운드 task 대기 중에도 stdin(= 권한 제어 채널)을
열어두므로, 연장 turn에서 `canUseTool` 경로가 살아 있다. Bash 권한과 **AskUserQuestion(→
탭 가능한 선택지 UI로 렌더링)**이 모두 작동한다. 따라서 **GATE 1·GATE 2 승인, 인터뷰·모호점 확인을
이 turn에서도 AskUserQuestion으로 받는다.** 텍스트로 "A/B/C 중 고르세요"를 제시하지 말 것 —
사용자가 음성이나 타이핑으로 글자를 지정해야 하는 부담을 만든다(이 스킬이 없애려는 바로 그 마찰).

이 turn에서 정상 작동: Read/Grep/Glob/Edit, Agent(리뷰어 호출), TodoWrite, **AskUserQuestion**,
settings allow 매칭 Bash. 산출물·로그는 여전히 cwd 안 `.orchestrate/`에 두어 경로 권한 프롬프트를
피한다(좋은 습관 — cwd 밖 경로는 allow 매칭돼도 별도 permission 프롬프트를 띄운다).

> **폴백 — Stream closed가 실제로 재발할 때만.** 클라이언트 업데이트로 스트리밍 입력 동작이
> 사라질 수 있다. 연장 turn에서
> `Tool permission request failed: Error: Stream closed`가 보이면 **채널 유실**이다. 그때만:
> AskUserQuestion·cwd 밖 Bash를 시도하지 말고, **텍스트로 A/B/C 선택지를 제시한 뒤 turn을 종료**한다
> (다음 사용자 발화는 새 프로세스라 채널이 살아 있다). 그리고 클라이언트의 스트리밍 입력
> 동작을 복구한 뒤 기본 규칙으로 돌아온다. 같은 도구 재시도 루프는 금물 —
> 채널은 프로세스가 살아 있는 한 복구되지 않는다.

**멈춘 것 같을 때**: 먼저 `tail -5 .orchestrate/task<N>.log`로 확인한다.
`loop session.id=... step=N` 이 올라가고 있으면 정상 작동 중 — 죽이지 말 것.
`message=init` 뒤로 진행이 없는 경우는 스크립트 내장 워치독이 2분 내 감지·종료·보고한다
(스크립트 없이 띄운 구버전 프로세스만 수동으로 같은 기준을 적용해 정리).
경합 상태는 **모든 opencode 프로세스가 끝난 뒤 잠시 두면 회복된다.**

정상 종료 신호는 로그의 `message="disposing instance"` 이다.

위임 프롬프트 구성 (**지시서의 해당 task만** — 전체 지시서 붙여넣기 금지.
task-orchestrator 경유 시에도 **이 구성과 위임 실행은 메인이 수행한다** — 6-A의 1):
1. **"먼저 `[실패 테스트]`를 작성하고 실행해 실패를 확인한 뒤 구현할 것"** (TDD 순서 강제 —
   리뷰 예상 지점에서 이 task에 배정된 RED 테스트가 있으면 반드시 포함)
2. **`재사용` 필드를 그대로** 넣는다 (경로·이름 명시) + "새 유틸·헬퍼를 만들기 전에 지정된 기존
   모듈에 같은 기능이 있는지 먼저 확인할 것" + "기존 함수를 복사해 수정하지 말 것 — 확장이
   필요하면 원본을 개선하고 호출부를 함께 갱신할 것"
3. 목표 / 대상 파일 경로 / 필수 규칙 요약
4. "작업 전 skill 툴로 `<스킬명>`을 로드할 것" (경로 아닌 이름으로 지정 — opencode가 네이티브 탐색)
5. 도메인 템플릿의 **금지사항 전체**
6. 공통 금지: 대상 파일 외 수정, `git commit`, docker 재시작
7. "완료 후 **수정한 파일 목록과 테스트 출력**을 보고할 것 +
   지시서에 없는 새 파일을 만들었다면 그 이유를 명시할 것"

## 7단계: 검수 (task마다)

> **task-orchestrator 경유 시**: 아래 1~3은 서브의 보고로 갈음하되, 보고의 검증 항목이
> **실제 명령과 출력 요약**인지 확인한다 (명령 없는 "통과" 주장은 미검증으로 취급).
> 4(리뷰어 병렬 호출)·5(판정)는 **메인이 수행**한다. 반려 시 findings를 붙여
> task-orchestrator를 재기동한다 (6-A의 4).

1. `git status --short` + `git diff --stat` — 대상 파일 외 수정 여부 확인
2. **테스트가 실제로 먼저 실패했는지** 확인 — 보고에 실패 출력이 없으면 TDD 미준수로 간주
3. 로스터의 **해당 도메인 검증 명령** 실행 (pytest, ruff, build, config -q 등) — 출력이 증거다
4. 로스터의 **리뷰어 매핑**에 따라 도메인 리뷰어를 **Agent 툴로 병렬 호출**한다.
   리뷰어에게 전달할 것: 변경 파일 목록, 지시서의 해당 task(`재사용`·`완료 조건` 필드 포함),
   `git diff`, 인덱스의 리뷰 예상 지점 표(있으면), 위임 로그 경로(`.orchestrate/task<N>.log`).

   **모든 리뷰어 호출 프롬프트에 아래 중복 검사를 포함한다** (ECC 리뷰어는 이 지시가 없으면
   diff만 보고 중복을 놓친다):
   > "diff에 새로 추가된 함수·클래스·상수 각각에 대해, 같은 일을 하는 기존 코드가 저장소에
   > 있는지 `grep -rn`으로 직접 확인하라. 발견되면 🟠 이상으로 보고하고 재사용할 기존 경로를
   > 제시하라. 지시서의 `재사용` 필드가 '재사용'인데 새로 만들었다면 🔴다."

   **리뷰어 계약 3항도 함께 포함한다** (ECC 실측 — ①은 커버리지 100%·CRITICAL 0에서도
   완료 기준 통누락을 검출, ②는 구현자의 "이월" 판정을 뒤집어 70곳 대신 7곳 수선안 도출):
   > "① 지시서의 완료 조건과 리뷰 예상 지점 **각각**에 대해 충족 여부를 명시 판정하라 —
   > 미충족·미언급 항목은 🔴다. ② 위임 로그의 구현자 주장('해당 없음'·'이월 가능'·'통과')을
   > 코드로 재검증하라 — 주장 인용만으로 판정하지 말 것. ③ 🔴·🟠 지적에는 재현 경로
   > (실행 명령+출력, 또는 구체적 입력→잘못된 결과 경로)를 첨부하라 — 재현 없는 지적은 🟡로 강등한다."
5. 판정:
   - ✅ 통과 (🔴 없음) → TODO.md `[x]` 마킹, 다음 task
   - ❌ 반려 (🔴 하나라도 있음) → 리뷰어의 수정 지시를 담아 **같은 에이전트에 heavy tier로 재위임
     (`run-delegation.sh ... heavy`, 최대 2회)** — 반려 재위임은 자동 heavy 승격이다.
     2회 실패 시 중단하고 사용자에게 원인 보고

> 리뷰어 호출은 도메인별로 **조건이 아니라 필수**다. "간단한 변경이라 생략"은 금지사항 위반이다.

## 8단계: 커밋 → **GATE 2 (페이즈 말 통합 승인)**

**task별 커밋**: task-orchestrator 경유 시 서브가 검증 통과 후 **로컬 커밋**까지 수행한다
(리뷰 반려 시 수정 커밋이 추가된다). 직접 위임(trivial·small) 경로에서는 현행대로
검수 통과 후 메인이 커밋한다.

**GATE 2 = 페이즈 말 통합 결과 승인** (task별 커밋 승인이 아니다): 페이즈의 모든 task가 끝나면
커밋 목록·`git diff --stat <페이즈 시작 커밋>..HEAD`·검증 총괄을 제시하고 AskUserQuestion으로
승인을 받는다. 전부 로컬 커밋이므로 되돌리기 가능하다. **푸시·병합은 GATE 2와 별개다 — 감독 체계가 있는 프로젝트는 CLAUDE.md "병합 주체" 조건으로 감독이 하고, 없는 프로젝트는 명시 승인 전용.**
**실자금 등 🔴 위험 도메인도 동일하게 통합 승인 1회로 진행한다** — task별 커밋 승인을
따로 요구하지 않는다 (비가역 경로가 비활성인 기간 기준. 재활성 시 재검토).
사용자가 되돌리기를 원하면 해당 커밋을 revert하고, squash를 원하면 지시대로 정리한다.
오토 모드에서는 120초 무응답(skip) 시 로컬 커밋 상태로 두되 프로젝트 세션의 푸시는 금지(병합은 감독 규칙, "오토 모드" 절 참조).

> **완료 알림 turn에서 GATE 2에 도달한 경우에도** (백그라운드 위임 완료 → 자동 재개 → 검수까지
> 마친 상황) **AskUserQuestion으로 승인을 받는다** — 2026-07-24 스트리밍 패치로 연장 turn에서도
> 작동한다(위 "완료 알림 turn" 절 참조). 텍스트 A/B/C 폴백은 Stream closed가 실제로 재발할 때만.

## 9단계: 완료 보고 + 문서 인덱스 갱신

- task별 결과 표 (에이전트 / 리뷰어 판정 / 검증 결과)
- 변경 파일 요약, 커밋 해시 (커밋한 경우)
- **정량 3필드** (지시서 frontmatter에도 기입): 비용 = `python3 scripts/session-cost.py` 실측 /
  auto-compaction 횟수·사람 개입 횟수 = 수기 카운트. **`session-cost.py`를 실행하지 않고
  `미측정`으로 남기는 것 금지** — 스크립트가 실제로 실패했을 때만 `-` (추정 금지 —
  ECC 교훈: 자동 기록은 원자료까지만 신뢰). 이 데이터가 워크플로우 개선의 판단 근거다.
  (이 단계가 누락된 실측 사례가 있다 — 2026-07-29.)
- 미해결·후속 제안

**페이즈 문서 관리** (문서가 쌓여도 과거 작업을 빨리 찾기 위한 체계):
1. 완료된 지시서(`docs/phases/PHASE<번호>_<slug>.md`)는 `status:`를 `done`으로 바꾸고 `commits:`·정량 3필드를
   채운다 (파일명에 번호가 있으므로 `docs/phases/archive/` 이동은 선택. 구식 `CURRENT_TASK.md`를 썼다면
   `docs/phases/archive/CURRENT_TASK_YYYYMMDD_phase<N>_<상태>.md`로 아카이브).
   분할 구조의 `.tasks/` 디렉터리는 지시서 옆에 그대로 남기되, `HANDOFF.md`는 페이즈 마감 시
   삭제한다 (인계는 페이즈가 살아 있는 동안만 유효한 임시 문서다).
2. 필요 시 페이즈 리뷰 문서를 `docs/phases/reviews/PHASE<N>_<slug>.md`로 남긴다 (frontmatter 포함: `phase/date/kind: review/domain/status/commits/summary`).
3. `python3 scripts/docs-index.py`(있으면)로 **`docs/phases/INDEX.md`를 재생성**한다. 인덱스는 손으로 고치지 말 것 —
   frontmatter가 소스이고 스크립트가 표를 만든다. 과거 작업 조회는 INDEX.md 표 스캔 → 문서 열기 → `git show <commit>`.
4. **이번 페이즈에서 실측된 새 함정**이 있으면 `docs/phases/PITFALLS.md`에 상세를 append하고
   (무엇을 하면 → 무엇이 죽는지 → 실측 날짜), 프로젝트 CLAUDE.md "이 저장소의 함정" 절에
   **한 줄 인덱스**를 추가한다 (상세를 CLAUDE.md에 쓰지 말 것 — 베이스라인 컨텍스트가 커지면
   autocompact 헤드룸이 줄어든다. PITFALLS.md가 없는 프로젝트는 같은 구조로 만든다).
5. **페이즈 마감 정리 = `bash scripts/phase-close.sh <번호>`** — 워크트리 제거(clean+병합 시)·
   병합된 로컬 브랜치 삭제·`.orchestrate/` 로그 아카이브·레지스트리 항목 제거를 원샷 수행한다.
   지시서 `status: done` 갱신이 선행 조건이다 (스크립트가 검사). 원격 브랜치는 저장소 설정
   `delete_branch_on_merge`(2026-07-31 활성)가 처리한다 — 새 저장소는 이 설정을 켠다:
   `gh api -X PATCH repos/<owner>/<repo> -f delete_branch_on_merge=true`.
6. **여기 도달하지 못하고 세션이 끊겨도** 다음 세션의 SessionStart 재니터
   (`orchestrate-janitor.sh`)가 안전급 잔재를 자동 정리하고 나머지(dirty 워크트리·미푸시·
   정체 PR·in-progress 방치 문서·메인 체크아웃 이탈)를 보고한다 (2026-08-03 도입 —
   프로즈 체크리스트는 세션과 함께 죽는다는 실측 교훈. 보고가 뜨면 무시하지 말고 처리한다).

## 금지사항

- 소스 코드(.py .ts .vue .js .go .css .yml 등) 직접 수정 — 반드시 위임
- `docker compose up/down/restart/build`, 패키지 설치
- 운영 컨테이너 조작, sudo
- 검수 없는 연속 위임 (task 하나 끝날 때마다 반드시 7단계 수행)
- 도메인 리뷰어 호출 생략
- `~/.claude/agents/`의 ECC 리뷰어 파일 직접 수정 (업데이트 시 덮어써진다 —
  조정이 필요하면 같은 이름으로 프로젝트 `.claude/agents/`에 사본을 만든다)

참고: 위임받는 에이전트 쪽도 frontmatter `permission`으로 `git commit`·`git push`·
docker up/down/restart·sudo·`rm -rf`가 기계적으로 차단되어 있다 (프로즈 규칙의 이중 안전장치).

## Red Flags — 이 생각이 들면 멈출 것

| 합리화 | 현실 |
|---|---|
| "한 줄 수정이니 직접 고치자" | 크기와 무관하게 소스는 위임. 직접 수정 가능한 건 docs/phases/·.claude/ 뿐 |
| "간단한 task니 검수 생략" | 검수 없는 위임이 금지사항 1순위. 검증 명령 출력 확인 전 ✅ 금지 |
| "요청이 대충 명확하니 인터뷰 생략" | 생략은 스코프·우선순위·제약이 **모두** 명시된 경우만 |
| "리뷰어까지는 과하다" | 리뷰어 호출은 조건이 아니라 도메인별 필수 |
| "테스트는 구현 후에 붙이면 된다" | 실패를 먼저 확인하지 않은 테스트는 구현에 맞춰진 테스트다. TDD 미준수 |
| "비슷한 게 있을 것 같지만 찾는 데 시간이 걸린다" | 찾지 않으면 중복이 확정된다. 재사용 조사는 지시서 작성자의 책임 |
| "문서·이전 지시서에 그렇게 적혀 있으니 맞겠지" | 적힌 전제는 실측 전까지 미검증이다. 뒤집힌 전제 1건이 페이즈 재작업을 만든다 (ECC 3회 실측) |
| "기존 함수를 고치면 다른 데가 깨질 수 있으니 새로 만들자" | 그게 중복의 시작이다. 호출부를 세어 함께 갱신하거나 별도 task로 분리 |
| "재사용 필드는 '없음'으로 두면 되겠지" | 근거 없는 '없음'은 조사 누락이다. 검색어를 함께 적을 것 |
| "이 도메인은 테스트가 어렵다" | 불가 사유를 지시서에 쓰고 대체 검증을 명시할 때만 허용. "어렵다"는 사유가 아니다 |
| "검증 명령이 실패했지만 코드는 맞아 보인다" | 출력이 증거다. 통과 전엔 실패로 판정하고 재위임 |
| "위임이 오래 걸리니 timeout으로 끊자" | SIGTERM은 에이전트를 죽이고 세션 DB까지 오염시켜 **다음 실행까지 막는다.** 로그를 보고 기다릴 것 |
| "사용자가 원하니 그대로 하자" | 비판적 검토가 요구사항이다. 대안·리스크를 먼저 제시 |
