# 실행 계획 — 모델 정책 프로젝트 스코프 + 한도 시그니처

> 상태: **미착수 (계획 문서 전용)**. 작성 2026-09-01, Phase 12 마감 직후.
> 구현 초안이 `fix/model-policy-project-local` 브랜치의 `04429d6` 에 있으나 **리뷰 REJECT** 로
> main 에 병합하지 않았다. 착수 시 이 문서를 지시서 입력으로 삼되, 초안을 그대로 쓰지 말 것.

## 동기 (사용자 요구, 2026-09-01 세션)

호스트 전역 `~/.config/opencode/model-policy.json` 하나가 이 호스트의 **모든 프로젝트**의 위임
모델을 결정한다. 프로젝트마다 다른 tier 체인을 쓰고 싶다는 요구가 나왔다.
부수적으로, 크레딧 소진(402)·usage limit 류 실패가 기존 `FAIL_RE` 에 안 잡혀 폴백이 안 걸린
사례가 관측돼 시그니처 확장이 함께 시도됐다.

## 초안(`04429d6`)이 한 것

1. `POLICY` 를 `$PWD/.orchestrate/model-policy.json` 우선 → 없으면 호스트 전역 폴백
2. `FAIL_RE` 에 `402`·`usage.?limit`·`spending.?limit`·`out of credits`·`insufficient.?credit`·
   `limit.*(reached|exceeded)` 추가, 라인 필터를 `grep -a 'ERROR'` → `grep -aE 'ERROR|Error:'` 로 확대

## 반려 근거 (bash-reviewer REJECT + 오케스트레이터 재현 확정)

### 🔴 시그니처·라인 필터 동시 확대 → 성공한 위임이 폐기될 수 있다

`model_error_in_log()` 는 **`OC_RC` 와 무관하게** 최종 판정에 쓰인다
(`run-delegation.sh` 419행: `elif model_error_in_log "$LOG_FILE"; then REASON="한도/프로바이더 에러 시그니처 rc=$OC_RC"`).
매칭되면 422행이 완성된 로그를 `.failed-<모델>` 로 옮기고 다음 모델로 폴백하며, 체인이
소진되면 `MODEL_EXHAUSTED` 로 전멸 보고된다. **rc=0 으로 정상 완료한 위임도 마찬가지다.**

확대된 두 축이 오탐 표면을 곱한다:
- `Error:` 는 code-reviewer·tdd-guide 류 위임 에이전트의 **정상 산출물**에 흔하다(린터 출력 인용,
  스택트레이스 인용, 리뷰 코멘트). 246~249행 주석이 명시한 "에이전트 산출물의 우연한 매치를
  막는다"는 설계 의도를 정면으로 약화시키는데, **그 주석은 수정되지 않아 코드와 불일치**한다
- `limit.*(reached|exceeded)`·`quota`·`usage limit` 은 평범한 영어 문장에서 나온다.
  `.*` 가 탐욕적이라 한 줄 안에 두 단어만 있으면 매칭된다

**비대칭**: 인터림 스톨 감시(348행·404행)는 여전히 `grep -a 'ERROR'` 만 쓴다. 같은 실행에서
"진행 중 판정"과 "종료 후 최종 판정"의 매칭 기준이 갈린다 — 의도인지 누락인지 불명.

### 🔴 프로젝트 로컬 정책이 재니터에 의해 7일 뒤 조용히 사라진다

`phase-tools.py` 422~437행(`오래된 .orchestrate 파일 → archive/old/`)은 `.orchestrate/` 하위에서
`archive`·`events.jsonl` **만** 제외하고, `STALE_LOG_DAYS = 7` 보다 오래된 항목을 전부
`archive/old/` 로 옮긴다. `.orchestrate/model-policy.json` 은 여기 해당한다 —
7일 뒤 SessionStart 재니터가 옮기고, 다음 위임부터는 **오류 없이** 호스트 전역으로 폴백한다.
"어제까지 되던 프로젝트 정책이 왜 안 먹히지"를 진단할 단서가 아무것도 남지 않는다.

### 🟡 `$PWD` 가 스크립트 관례(`RUN_DIR`)와 불일치

66행이 이미 `RUN_DIR=$(pwd -P)` 로 물리 경로를 잡아 `opencode run --dir "$RUN_DIR"` 에 쓴다.
69행만 논리 경로 `$PWD` 를 쓴다. `set -u` 하에서 `env -i` 호출 시 unbound 위험도 있다.
또 프로젝트 **하위 디렉터리**에서 호출하면 로컬 정책을 못 찾고 조용히 전역으로 폴백한다.

### 🟡 정책 부재 오류가 두 후보 경로 중 하나만 보여준다

77행 `emit "정책 파일 없음: $POLICY"` 시점의 `$POLICY` 는 이미 전역 경로로 덮어써져 있다.
로컬 오버라이드를 시도했다는 사실 자체가 사용자에게 보이지 않는다.

### 🟡 `.orchestrate/` 는 gitignore 대상

프로젝트 로컬 정책이 저장소와 함께 이동하지 않는다. 호스트 인증에 묶인 값이라 의도된 설계일
수 있으나 **문서화되지 않았다**. 위치 선택 자체를 재검토할 것 (`.orchestrate/` vs 추적되는 경로).
